## 1. 概要

### 背景・目的

電源をつなぐだけで、オーナーの YouTube Music プレイリストが Bluetooth スピーカーから流れる Raspberry Pi 4B 単体完結の小型端末。端末自身が Wi-Fi AP を立て、LCD の QR → キャプティブポータルでスマホから操作する。ゲストはアプリ・アカウント不要でキューに曲を追加できる。外部サービス（中継サーバー・Tailscale 等）に依存しない。

### スコープ内（本サイクル = 開発 PC で検証可能なソフトウェア）

| 区分 | 内容 |
| --- | --- |
| 再生 | mpv JSON IPC ラッパ、キュー（プレイリスト + ゲストキュー）、制御デーモン（状態機械・次曲先読み・resolve 失敗スキップ・ローカル MP3 フォールバック・ウォッチドッグ通知） |
| 音源 | アダプタ I/F（4 関数、既存 `base.py` を変更しない）、ローカル MP3（コア同梱）、YouTube Music アダプタ（別パッケージ） |
| 端末制御 | Wi-Fi（nmcli ラッパ）、Bluetooth（bluetoothctl ラッパ）、キャプティブポータル（接続検知 URL 応答・dnsmasq 設定生成） |
| Web | FastAPI + 外部 CDN 不使用の単一 HTML。ゲストビュー / オーナービュー（PIN） |
| LCD / タッチ | 状態別画面の描画（PIL）、RGB565 変換と `/dev/fb1` 書き込み、QR、回転レコードのフレーム事前生成、タッチ判定 |
| 運用 | systemd unit / timer（デーモン、yt-dlp 更新、ヘルスチェック） |

### スコープ外

- 実機でしか判定できない受け入れ（A2DP 30 分、STA+AP 同時動作、起動時間、電源ブチ切り、QR 1m 読取、overlayfs 構築、温度）→ §3 で「実機検証（人間）」として区別
- ケース CAD・印刷（Autodesk Fusion で人間が実施。仕様は `input/SOIKAXA.md` v0.6）
- v2 以降: ネットラジオアダプタ、シャッフル・リピート、投票、WireGuard 遠隔操作、Spotify
- スリム版 SoiKaxa Txiki（Zero 2 W）の移植（設定に機種名フィールドのみ持つ）
- 販売・キット化、キャプティブポータル型フリー Wi-Fi の自動突破、Amazon Music、DRM 回避

### ケース仕様の更新（一次情報間の差分）

一次情報 PRD v4.1 §11（PETG、ヒートセットインサート ×4、外寸 95×65×30）は `input/SOIKAXA.md` v0.6（2026-11-21）で置換された: 黒 PLA + オレンジ PLA、スナップ爪 ×4、本体 約 93×61×30（台座込み全高 約 37）、ファンなし・底面 45° スリット吸気、開口は USB-C と microSD のみ、70℃超が続く場合はボトムのみ PETG で再印刷。ソフトへの影響は「温度ログ（`vcgencmd measure_temp`）をヘルスチェックに含める」のみ。

## 2. 用語定義

| 用語 | 定義 |
| --- | --- |
| オーナー | 端末の所有者。PIN で設定・音量・キュー編集を行う |
| ゲスト | 端末 AP に参加した友人。検索とキュー追加のみ可能 |
| 端末 AP | 端末が常時立てる Wi-Fi アクセスポイント `soikaxa-XXXX`（XXXX は MAC 下位 4 桁） |
| 上流 Wi-Fi（STA） | 端末がインターネットに出るための Wi-Fi（自宅・会場・テザリング） |
| キャプティブポータル | AP 参加直後に OS が自動で開く Web 画面。iOS/Android の接続検知 URL に応答して発火させる |
| ソースアダプタ | 音源を 4 関数（`list_playlists` / `list_tracks` / `search` / `resolve`）で抽象化した部品 |
| resolve | 再生直前に曲 ID を mpv に渡せる URI（URL またはパス）へ解決すること |
| ゲストキュー | ゲスト・オーナーが追加した曲の列。プレイリストより優先して再生される |
| 次に流す | キューの先頭に割り込ませる操作 |
| ヘルスチェック | 既知の曲 1 つを resolve して音源の稼働を確認する定期処理 |

| FR-002 | 選択したプレイリストを順番に連続再生し、キューを優先する（F-02） | Must | 曲終了（EOF）で次曲へ進むこと / キューが空でなければキュー先頭がプレイリスト次曲より先に再生されること / 最終曲の後は IDLE になること | U |
| FR-003 | resolve 失敗時はスキップする（PRD 9, base.py） | Must | `AdapterError` を送出した曲はログを残して次曲へ進むこと / 連続失敗が閾値（既定 3）に達したらローカル MP3 アダプタへ自動切替すること | U |

| FR-008 | 上流 Wi-Fi を複数登録し自動選択、AP と同時動作（F-06） | Must | 登録 SSID を NetworkManager 接続プロファイルとして作成すること / 自動接続優先度を設定できること / AP チャンネルを STA チャンネルに追従させるコマンドを発行すること | U / R |
| FR-009 | Wi-Fi 登録 3 経路（F-07, 9.2） | Must | 一覧（スキャン結果）から選べること / 手入力でステルス（`hidden=yes`）を指定できること / 撮影画像の Wi-Fi QR を端末同梱の JS で解読し SSID・パスワードを自動入力すること / 入力欄が `autocorrect=off autocapitalize=off spellcheck=false` であること / 保存前に文字数付き確認を表示すること / 接続失敗を「パスワード違い」「ステルス未指定」「キャプティブポータル」に分類して返すこと | U |
| FR-010 | オーナーとゲストの権限分離（F-08） | Must | オーナー API は PIN 認証済みセッションのみ受け付けること / ゲストはオーナー API・認証情報・オーナープレイリストに到達できないこと / オーナーがゲスト受付を停止できること / PIN 誤入力が続くとロックされること | U |

## 5. データモデル

新規プロジェクトのため既存データなし。設定は JSON 1 ファイルで、`schema_version` を持ち、未知キーは無視・欠損キーは既定値で補完する（後方互換）。

| エンティティ | 主な項目 | 永続化 |
| --- | --- | --- |
| Settings | schema_version, device_model, owner_pin_hash, ap_ssid, ap_password, autoplay, last_playlist(adapter, id), active_adapter, volume, guest_enabled, allow_play_next, guest_queue_limit, brightness | `<data>/settings.json`（0600） |
| WifiProfile | ssid, label, hidden, priority | NetworkManager が保持（パスワードは NM に渡し settings には残さない） |
| BtDevice | mac, name | settings の `known_speakers` |
| QueueItem | item_id, track（Track）, added_by, guest_id, added_at | メモリのみ（再起動で消える） |
| 音源認証 | アダプタ固有ファイル（`browser.json`） | `<data>/adapters/<name>/`（0600） |

`<data>` は既定 `/var/lib/soikaxa`、環境変数 `SOIKAXA_DATA_DIR` で切替。PIN は scrypt ハッシュ + ソルトで保存し平文を残さない。

## 7. 技術的考慮事項

技術スタックは一次情報（D-01〜D-16、PRD 8〜9 章）で人間が決定済み: Python + mpv + yt-dlp + ytmusicapi + BlueZ + PipeWire + NetworkManager + dnsmasq + FastAPI + PIL + qrcode + evdev。本 PRD では追加選定しない。

- コアは YouTube を知らない。音源は `adapters/base.py` の 4 関数のみ（D-08, D-09）
- YouTube Music 固有コードは `adapters/soikaxa-adapter-ytmusic/`（将来は別リポジトリ）
- 外部コマンドは注入可能な実行抽象を経由し、テストで Mock できること
- mpv・BlueZ（GPL）は別プロセスとして呼び出し、コアのライセンスに伝播させない
- jsQR（Apache-2.0）を Web 画面に同梱する必要がある（CDN 不可）→ 法務チェック対象。代替: 未同梱時は手入力へフォールバック

| # | 事項 | 【仮定】PJM 判断 | 代替案 / 影響範囲 |
